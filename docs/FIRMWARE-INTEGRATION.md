# Native RUPTURE V1.2

- FM1 firmware `vendor/etch-v1.88-source/firmware/fm1-native/bringup.c` implements the step navigation and keyboard triggers. Keys are edge-detected and only edit while stopped (or overdub when REC is engaged).
- K1 lengths 4/8/16/32/64/128, K2 project/native BPM 30..240, K3 note-entry velocity, K4 gate. SELECT chooses the step. Active playback and REC are distinct states.
- `rupture_ui.c` is the only native 1-bit renderer; PNGs are byte-for-byte interpretations of those pixels generated by `rupture_host_export.c`.
- ARP 0=OFF; 1 UP; 2 DOWN; 3 UPDOWN; 4 ORDER; 5 RANDOM; 6 CUSTOM; 7 RIFF.
- Boot logo is drawn as soon as LCD+interrupts are available, before storage and DSP initialization. The ROM boot interval cannot be drawn on.
- Native P05 four-project snapshot area and eight sequence slots remain unchanged. No extra flash sectors.
- Original V1.88 16 KiB protected boot header and OTA loader are identical in the new `.fwsc`.
- The separately executed OTA loader retains its original appearance, as required for recovery.
- Interface and audio performance remain unconfirmed on a physical FM1 in this environment.

Trusted OTA loader cannot be forced to display RUPTURE LCD progress without a separate loader replacement project. The browser shows true bytes-served progress while loader controls the device.

RUPTURE-specific EQ: K4 uses the saved optional eq_hpf word as HIGH CUT instead of legacy ETCH HPF; compiled only under RUPTURE_BUILD.

V1.2: UART1 TRS MIDI input added via fm1_uart.h and rupture_trs_input.h, DMA buffer 256 bytes, source=2 to the existing 64-event audio ring. Test on physical FM1 still required.


## V1.5 capacity-bounded twelve-slot catalog

`wave_store.c` supports PJ52/version 13: a twelve-slot manifest in the existing ETCH-owned `0xB4000..0xDC000` dual-bank area (80 KiB per copy). The code can read PJ51/version 11/12 four-entry catalogs, and writes the new 12-entry catalog on an explicit save. Every survivor is streamed and individually CRC-verified. The new header commits only after the new bank passes total and per-entry CRC checks. No new flash sectors are erased. If a project does not fit the available bank, SAVE returns `ETCH_STORE_FULL` without modifying the previously committed snapshot. Older firmware cannot decode PJ52; backup/restore is mandatory before downgrade.
