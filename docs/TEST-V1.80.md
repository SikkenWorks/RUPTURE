# RUPTURE V1.80 — Reverb Quality & DSP Efficiency Audit

Date: 2026-11-04. Starting project: supplied complete V1.79 native source. Software-built candidate, **not certified for live or studio use**. This report distinguishes tests that ran from physical listening/latency still requiring an FM1.

## On-device evidence provided by the user

After V1.79 the user reported **DMA LATE = 1, GUARD = 1**. These are cumulative counts. A reading of 1 does not reveal whether there is a currently recurring underrun or only an earlier startup event. The user also reported that the V1.78/V1.79 SPRING and ROOM reverbs were musically unsatisfactory. That qualitative complaint cannot be resolved by statistics alone.

## Confirmed structural problems and changes

- **V1.79 ROOM:** one feedback ring read from a few delayed taps, plus two early taps; this did **not** make a genuine network of different room-reflection paths. **V1.80 ROOM:** four separately advanced delay lines (maximum lengths 727, 881, 1013 and 1475 samples) in a four-channel Householder feedback-delay network with damping; the SIZE control changes each actual delay length. DECAY changes feedback gains. Output has decorrelated left/right returns. The geometry is still a compact algorithmic approximation, not measured impulse responses from a real room.
- **V1.79 SPRING:** a single-feedback ring with alternating-sign taps, causing a harsh and rapidly repeating metallic character. **V1.80 SPRING:** two independently circulating waveguide paths (maximum lengths 2039 and 2057 samples), two short cascaded dispersive allpasses in the existing 64-sample diffuser and a limited portion of the recirculating energy fed through the dispersion again. Wet excitation is gently low-filtered, feedback is bounded. This is a spring-inspired algorithm, **not** a physically exact model of a particular tank.
- **HALL remains the previous HALL algorithm.** The user has not reported an HALL defect; avoid modifying it incidentally. Golden full-chain PCM from V1.79 vs V1.80 for HALL: **identical SHA-256 `94f25ff864ee3d88c1c5ed0211950219e413f2db7e6bc35157c7325576a5396c`** across 260,000 output bytes.
- **Wet 100%:** the existing true-wet interpolation is retained. Room/Spring wet returns have been rebalanced at their output stages, with the existing wet-safety knee still limiting peaks to 28,000 Q15. No second reverb engine or additional PCM buffer was allocated.
- **Q15 DSP optimizations:** remove unnecessary 64-bit products/divisions for safe, bounded sections of phaser, wah, tape, tremolo and decimator, retaining the same truncation rules. All other reverb coefficient divisions were moved into the existing settings-change calculation rather than the sample loop. Previous SUB DRIFT optimization retained.

## CPU statement

New ROOM requires four independent memory read/write operations and extra diffusion work, unlike the V1.79 sparse-tap algorithm. SPRING adds recirculating dispersers. Exact Q15 reductions elsewhere save work, but a **guaranteed lower maximum DSP percentage at every parameter setting is not proven**. Host wall-clock microbenchmarks vary and are not valid FM1 cycle measurements. It would be misleading to promise zero hardware underruns or that a more sophisticated reverberator is always cheaper than the simplistic previous implementation.

## OTA/integrity

`audio_core.c`, `ota.c`, native project serializer, ISR assembly and the M-VAVE firmware identity remain unchanged. The first protected 16 KiB of `flash.bin` and the OTA-loader payload are byte-identical to the V1.79 firmware; the new `app.bin` is packaged inside the same validated update layout. WebInstaller and `.fwsc` SHA-256 must be the same and checked by build scripts.

**Hardware acceptance before live/studio confidence:** backup projects, use verified Pico rescue hardware, reboot FM1 and note all counters, stress both SUBs / DRIFT, active FX, all three reverb types at 0/50/100 MIX, extreme SIZE/DECAY, USB MIDI/audio, and rapid UI movement. Require LATE/GUARD to remain unchanged, positive MIN SLACK, no audible clicking or extra clipping, and acceptable Room/Spring sound for the user. If counters increase, stop treating V1.80 as live-stable and capture diagnostic values and reproduction steps.
